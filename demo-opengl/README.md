# demo-opengl

A small CShift project using OpenGL 3.3 (core profile): a rotating, rainbow colored cube, drawn with a vertex and a
fragment shader. The window and the OpenGL context come from [GLFW](https://www.glfw.org); OpenGL's constants and
function signatures come from the official Khronos header `GL/glcorearb.h`. **Esc** closes the window.

```
demo-opengl/
├── cshift.json        project file (sources, header path, defines, libraries)
├── src/
│   ├── main.csh       entry point: window, shaders, cube, render loop
│   ├── gl.csh         loads the OpenGL functions at run time (LoadGl)
│   └── matrix.csh     Mat4: perspective, rotation, translation, multiplication
├── include/
│   ├── gl33.h         the OpenGL functions the demo uses, as a struct of function pointers
│   ├── GL/glcorearb.h Khronos OpenGL core profile header (MIT)
│   ├── KHR/khrplatform.h
│   └── GLFW/glfw3.h   GLFW 3.4 header (zlib license: include/LICENSE-GLFW.md)
├── get-glfw.ps1       downloads the GLFW library for Windows into lib/
├── lib/               libglfw3.a (generated by get-glfw.ps1, not in git)
└── bin/, obj/         output and FFI intermediates (generated, not in git)
```

## Building and running

Prerequisite: `cshiftc` and `clang` are on `PATH` (see [../README.md](../README.md)), and a GLFW library. Either:

```powershell
.\get-glfw.ps1                                   # official GLFW 3.4 binaries -> lib\libglfw3.a (static)
pacman -S mingw-w64-clang-x86_64-glfw            # or: MSYS2 CLANG64 (needs glfw3.dll from clang64\bin at run time)
```

Then:

```powershell
cshiftc run          # build and run
cshiftc build        # build only  ->  bin/demo-opengl.exe
```

The program prints the OpenGL version and renderer it got. In VS Code (with the CShift extension): **Ctrl+Shift+B**
builds, *Tasks: Run Task → cshiftc: run* runs the program.

**Linux:** install GLFW (`sudo apt install libglfw3-dev`) and change `links` in `cshift.json` to `["glfw", "GL"]`
(the library is called `libglfw.so` there; `gdi32`, `user32` and `shell32` are Windows libraries).

## How it works

* **Headers.** `using Glfw from "GLFW/glfw3.h";` imports GLFW, `using Gl from "gl33.h";` imports OpenGL. The define
  `GLFW_INCLUDE_NONE` (in `cshift.json`) keeps GLFW from including the old `GL/gl.h`.
* **Loading OpenGL.** On Windows, `opengl32.dll` only exports OpenGL 1.1; everything newer has to be looked up at run
  time once a context exists. `include/gl33.h` therefore declares `struct GlFunctions` with one field per function,
  typed with `glcorearb.h`'s `PFNGL…PROC` typedefs. The FFI import turns each field into an `Action<…>`/`Func<…>`
  with the right signature, and `LoadGl()` in `src/gl.csh` fills them in via `glfwGetProcAddress`:

  ```csharp
  Load(ref gl.CreateShader, "glCreateShader");   // gl.CreateShader: Func<uint32, uint32>
  ...
  uint32 shader = gl.CreateShader(Gl.GL_VERTEX_SHADER);
  ```

  To use another OpenGL function, add a field to `GlFunctions` and a `Load(...)` line to `LoadGl()`.
* **Libraries.** `links` lists GLFW (`glfw3`), OpenGL (`opengl32`) and the Windows libraries a static GLFW needs
  (`gdi32`, `user32`, `shell32`). `libraryPaths: ["lib"]` makes the linker find `lib/libglfw3.a`.
* **The cube.** 8 corners, each with a color of the rainbow, and 36 indices (6 faces × 2 triangles) in a vertex
  buffer, an index buffer and a vertex array object. Every frame, the model-view-projection matrix (`Mat4` in
  `src/matrix.csh`, column-major like OpenGL expects) goes to the vertex shader as the uniform `uMvp`; the fragment
  shader outputs the interpolated color. The shaders (GLSL `#version 330 core`) are at the top of `src/main.csh`.

[../FFI.md](../FFI.md).
