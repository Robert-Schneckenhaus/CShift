# demo

A small CShift project for trying out the language: a window with animated plasma, drawn via the C library
[MiniFB](https://github.com/emoon/minifb). It shows C header import (`using Mfb from "MiniFB.h";`) and callbacks
(`Action<…>`/`Func<…>`): MiniFB calls `OnKey` and `OnClose` in `src/main.csh`. **Esc** closes the window.

```
demo/
├── cshift.json        project file (sources, header path, libraries)
├── src/
│   └── main.csh       entry point: int Main()
├── include/           MiniFB header (MIT license: include/LICENSE-MiniFB)
├── build-minifb.ps1   builds libminifb.a
├── libminifb.a        (generated by build-minifb.ps1, not in git)
└── bin/, obj/         output and FFI intermediates (generated, not in git)
```

## Building and running

Prerequisite: `cshiftc` and `clang` are on `PATH` (see [../README.md](../README.md); on Windows, easiest from the
MSYS2 CLANG64 shell, or with `C:\msys64\clang64\bin` on `PATH`).

Build the library once (this also needs `cmake`, `ninja` and `llvm-ar` from MSYS2 CLANG64, plus a MiniFB checkout):

```powershell
.\build-minifb.ps1 -Source C:\path\to\minifb
```

Then:

```powershell
cshiftc run          # build and run
cshiftc build        # build only  ->  bin/demo.exe
```

The commands look for `cshift.json` in the current folder and its parents, so they also work from `src/`. From
outside the folder: `cshiftc run demo`.

In VS Code (with the CShift extension): **Ctrl+Shift+B** builds, *Tasks: Run Task → cshiftc: run* runs the program.
Compiler errors show up in the Problems panel.

The library must be built with clang (COFF objects). A `libminifb.a` built with tcc contains ELF objects and can't be
linked (`unknown file type`).

## How the header is imported

* `"includePaths": ["include"]` tells the compiler where `MiniFB.h` lives. The first time it builds, it parses the
  header with libclang and creates `obj/ffi/Mfb.ffi`; after that it's only reparsed when the header changes.
* `"links"` lists the library (`libminifb.a`, a file) and the Windows libraries (`gdi32`, `opengl32`, `user32`,
  `winmm`).
* Everything from the header lives in the `Mfb` namespace: `Mfb.mfb_open_ex(...)`, `Mfb.mfb_window*`,
  `Mfb.MFB_WF_RESIZABLE`, …. Details: [../FFI.md](../FFI.md).

## Extending it

* New `.csh` files in `src/` (including subfolders) automatically become part of the program. All files are compiled
  together, and types and functions are visible everywhere without `using`/a header. Use `namespace MyNamespace;` on
  the first line of a file and `using MyNamespace;` in others to organize things.
* The standard library (`List<T>`, `Dictionary<K,V>`, `File`, `Math`, string helpers, …) is always available.
* More callbacks (`mfb_set_mouse_move_callback`, `mfb_set_resize_callback`, …) are functions with the matching
  `Action<…>` type.

The project file's format is described in [../BuildDesign.md](../BuildDesign.md).
